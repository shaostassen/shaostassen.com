## A discrepancy found while sourcing, and flagged to Shao

`DriveBench` currently reports **zero** banked damage across eight
consecutive full-speed rams ("no panel broke in 8 rams -- integrity is out of
reach"), with the chassis-side peak reading 441 N against a documented ~700 N.
`MatchBench` agrees from the other direction: a full spinner-vs-wedge match
finishes with `damage taken wedge 0 N·s, spinner 0 N·s, panels shorn 0`.

The spinner path is unaffected — `SpinnerBench` shears a panel off the dummy
in one full-RPM strike (57.3 N·s banked). So the damage model works; it is the
wedge-vs-armour path that no longer reaches tolerance.

This is arguably the documented design intent ("a plow is a ramp... it should
struggle to shear armour"), and arguably a regression against the numbers in
the same docstring. Either way it is the game repo's call, not the website's.
Reported to Shao rather than fixed here, and the page simply makes no claim
that depends on it.

## Decisions

- **`category: robotics`, not `graphics`.** Chosen by Shao when the scope was
  confirmed. It files next to Huey, and the domain knowledge — Cornell Combat
  Robotics — is the thing that makes the project credible. Super Gold Hunters
  keeps `graphics` as the renderer-from-scratch entry.
- **`status: in-progress`.** M0–M5 are built, but `IDEAS.md` lists three open
  soft spots and the hammer demonstrably under-delivers. `complete` would be
  a claim the bench does not support.
- **Lead "What I'd do next" with the hammer, not with polish.** Per
  `content-voice`, that section is real judgement: the hammer's failure has a
  measured cause (recoil into the chassis, 204 mm of its own nose lifted
  against 44 mm of victim) and a concrete fix.

## The video

Recorded with Godot's own Movie Maker mode (`--write-movie`) at 1920×1080/60,
then cut and encoded to 1280×720/30 H.264, 26 s, 1.8 MB. Follows the S3.3
pattern exactly: `preload="none"`, poster image, `aria-describedby` tying the
silent clip to its caption, pinned by a smoke test.

**The poster is WebP, not PNG** — the one deliberate break from the S3.3
pattern. Super Gold Hunters' poster is a flat-shaded raycast frame, which PNG
encodes efficiently (51 kB). This one is a lit 3D render: full-colour PNG
costs 147 kB at 960 px, and palette-quantising it down to 55 kB banded the sky
and shifted the wedge's orange accent to red. WebP is 16 kB with neither
problem. The first pass shipped a 1280 px, 124 kB PNG and the page measured
**91** — one point above the floor, and the largest asset on it. At 960 px
WebP it measures **95**.

Recording notes, all of which cost time:

- **Recorded from a throwaway copy of the project**, never the repo itself.
  The copy gets an AI driver on the wedge (the game ships it player-driven, so
  an unattended recording would show a bot sitting still being counted out), a
  `Recorder.gd` that quits a few seconds after the bout is decided so the AVI
  closes cleanly, and a tightened chase camera. Nothing in Shao's repo was
  touched.
- **`Match.tscn`, not `Tournament.tscn`.** The tournament is already fully
  simulated, but its `WorldEnvironment` is bare — the SDFGI, volumetric fog,
  glow, spotlight rig, HUD, and kill cam all live in the match scene.
- **The chase camera was pulled in** (distance 6.0 → 5.0, height 3.0 → 2.2).
  At the stock framing the machines are a few percent of frame width. This is
  a camera parameter the game already exposes, not an art change.
- **The kill cam is cut out of the clip.** On this finish the beaten wedge
  stopped against a wall, so the orbit passed through it and produced ~3 s of
  flat red. Cutting around it is why the clip is three excerpts rather than
  one continuous run.
- **`KillCam` times off `Time.get_ticks_msec()`** — wall clock — while Movie
  Maker renders at ~65% of real time. The replay is therefore shorter in the
  recording than it is in play. Worth knowing before anyone records again.
- Takes are near-deterministic: four runs came out 2829–2833 frames. Shooting
  more takes to get a different fight does not work; the fight has to be
  changed.

## The playable option (offered, declined)

Priced for Shao at scope-confirmation time and not built:

- Export templates for 4.7.1 are not installed (~1 GB download).
- The project renders **Forward+**; Godot web export needs Compatibility
  (WebGL2). SDFGI and volumetric fog — most of the spectacle pass — do not
  survive that port, so the web build would look materially worse than the
  clip.
- Threads-enabled web builds need COOP/COEP headers, which the static export
  cannot set on GitHub Pages without breaking the host-portability rule in
  PLAN §3. The single-threaded fallback runs 120 Hz Jolt in wasm.

If it is ever wanted, the click-to-load poster pattern this page already uses
for the video is what keeps a 30–50 MB payload off the Lighthouse budget.

## Gotchas

- `pnpm` needs Node ≥ 22.13; the shell's default `node` on this machine is
  v18.16.0 and every script fails with a version error until
  `~/.nvm/versions/node/v22.23.2/bin` is on PATH.
- `ffmpeg` on this machine has **no `libwebp`**. The poster's `.webp` was
  generated with `sharp`, which the repo already depends on for the photo
  pipeline.
- `godot --headless --import` does not compile GDScript — only a script run or
  a game boot does. Carried over from `IDEAS.md`; still true on 4.7.1.
