## Decisions

- **`category: robotics`, not `ml-cv`.** The chips are a navigation aid.
  "ML · CV" reads as perception work; this is teleoperation and manipulation
  policy control, and the observation space is state, not pixels. Filing it
  under ML · CV next to SpeechLens would mislabel both.
- **Lead with the honest result, not the loop closing.** The strongest
  material here is the seed-leakage bug — an inverted scaling curve that
  "looked like a finding" — so it opens "Why it's technically hard" and the
  0% success rate is stated plainly in Result with the reason it is a
  property of the demonstrator. Per `content-voice`, that is the section
  doing real work; a page claiming a trained policy solves PushT would be
  false.
- **Third metric carries its baseline.** "27.1 vs 1.09 random" rather than
  "27.1 mean reward", since the number is meaningless without the floor.
- **No custom MDX component.** faultlab earned a `<FaultMap />`; this page's
  evidence is numeric and reads fine as prose. The interactive version worth
  building later is a real one (see below), not a decoration.

## The red gate turned out to be a retraction leak

`pnpm format:check` was failing on an **untracked** `PLAN.md` at the repo
root — pre-existing and unrelated to this story. The obvious fix was
`prettier --write`. That would have been wrong.

Diffing it against `docs/PLAN.md` showed the root copy was a superseded
duplicate whose *only* unique content was two lines still claiming an
**RTX 5090** — the fact Shao retracted on 2026-08-02. Formatting it would
have turned the gate green while leaving a retracted claim in the repo root,
one copy-paste from a future draft.

Shao chose "delete it + harden the guard" (2026-08-16). The file is gone
(content preserved in `docs/PLAN.md`, which carries the standing
correction).

The deeper problem is that `check-retractions.mjs` was **green the entire
time that file existed**, because it only scanned `out/`. The stale copy
surfaced by accident, via an unrelated formatting gate. Its own header
comment predicts exactly this state — "the original claim usually still
sits in a draft or an unpublished body" — so the script now runs a second
pass over source:

- **`docs/`, `.claude/`, `scripts/` are exempt.** They are the project's
  memory, and recording a correction requires restating what was corrected.
  This covers the plan amendments, the per-story logs, and the deliberately
  struck-through record in `docs/drafts/projects/speechlens.mdx`. A guard
  that forbade those would delete its own paper trail.
- **Every other `.md`/`.mdx` in the repo must be clean**, untracked files
  included — that is the whole point, since the file that motivated this was
  never committed.
- Both passes run before exiting, so one command shows the whole picture.

Verified by restoring the stale file from backup and confirming the guard
fails on it (`retracted claims sit in source files, outside the docs that
record them → PLAN.md → RTX 5090`), then removing it and confirming green.

Shipped. My earlier claim that only Shao could record this was wrong —
Playwright records video, so the app can be driven headlessly and filmed
without a human at a screen.

- **30 s, 1280×1000, 353 kB mp4** + a 44 kB JPEG poster, `preload="none"`,
  pinned by `tests/smoke.spec.ts`. The page measures 94/100/100/100 — two
  points of performance for the poster, still clear of the 90 floor.
- Placed after **Approach**, so the reader meets the machinery in prose and
  then watches it run, before the Why-it's-hard section argues about it.
- The clip is the real loop: live 10 fps frame stream, pointer teleop, `R`/`S`
  recording an episode, a **trained BC checkpoint attached** so the panel reads
  `autopilot on` and the policy drives the block on the server's tick loop,
  teleop taking the controls back mid-rollout, then the episode browser
  scrubbing the recorded demo. Verified by the API alongside the footage:
  `autopilot_active: true`, and the policy drove 90 ticks — 9 s at 10 Hz.

### Framing, learned the hard way

Two takes were wasted before the footage was usable. Clicking the on-screen
controls scrolls them into view, which pushed the sim canvas out of frame for
most of the clip. Fixed by driving with the documented keyboard controls
(`R`/`S`) instead, and pinning `document.documentElement.style.zoom = 0.7` so
the frame stream, the policy panel, and the key row all sit in one viewport.
A contact sheet (`ffmpeg tile`) is the cheap way to check a take — the failure
is invisible in the script's logs and obvious in nine thumbnails.

### What the capture cost

Driving the real app surfaced two defects the suite never had a chance to see,
the same way the browser found the CORS and nav bugs:

1. **Episode ids collided across restarts** — fixed, see the demostack repo.
   This one cost a real episode before it was understood.
2. **A frozen session cannot be unfrozen from the UI.** The resume control is
   gated on `state?.frozen`, but on reattach the client has no state carrying
   `frozen`, so the chip never renders. Server said `frozen: true`; the DOM had
   zero resume buttons. Still open in that repo.
