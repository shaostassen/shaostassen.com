## Decisions

- **`category: robotics`, not `ml-cv`.** The chips are a navigation aid.
  "ML · CV" reads as perception work; this is teleoperation and manipulation
  policy control, and the observation space is state, not pixels. Filing it
  under ML · CV next to SpeechLens would mislabel both.
- **Lead with the honest result, not the loop closing.** The strongest
  material here is the seed-leakage bug — an inverted scaling curve that
  "looked like a finding" — so it opens "Why it's technically hard" and the
  0% success rate is stated plainly in Result with the reason it is a
  property of the demonstrator. Per `content-voice`, that is the section
  doing real work; a page claiming a trained policy solves PushT would be
  false.
- **Third metric carries its baseline.** "27.1 vs 1.09 random" rather than
  "27.1 mean reward", since the number is meaningless without the floor.
- **No custom MDX component.** faultlab earned a `<FaultMap />`; this page's
  evidence is numeric and reads fine as prose. The interactive version worth
  building later is a real one (see below), not a decoration.
