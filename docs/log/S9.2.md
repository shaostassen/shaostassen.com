# S9.2 — Self-hosting kit

Status: done · Started: 2026-08-07 · Shipped: 2026-08-07

Shao asked whether the site could run on his own server so the only bill is
the domain, and chose to self-host. This story delivers everything needed to
do that; it does **not** move DNS — production is still Vercel until he cuts
over.

## The correction that shaped the story

The premise needed adjusting before any work started: **AWS is not hosting
the site.** Vercel Hobby serves it for $0. AWS's only roles are DNS
(~$6/yr for the Route 53 hosted zone) and the registrar (~$14/yr).

So self-hosting saves **nothing** by itself — the only recurring non-domain
cost is the hosted zone, and moving files to a home box does not touch it.
Told plainly, with the cheaper alternative (Cloudflare DNS, stay on Vercel)
recommended. Shao chose self-hosting anyway, which is a legitimate call for
control rather than cost, so the work proceeded on that basis and the
trade-off is stated at the top of `docs/SELF-HOSTING.md` rather than buried.

There is one genuine technical gain: the OG cards. Next writes them without
a file extension, Vercel types them `application/octet-stream`, and there is
no `vercel.json` to override it. Self-hosting means owning the MIME table,
so the configs here fix a bug that has been live since S7.2.

## Approach

The risk with hosting config is that it is written once, never exercised,
and wrong in a way nobody sees until it is live. So the rules are defined
**once as executable code** and tested:

- `scripts/serve-static.mjs` — the reference server. Implements the whole
  ruleset and is now what Playwright runs against, replacing `serve`. All
  180 tests exercise it, so the ruleset is proven by the existing suite
  rather than asserted.
- `tests/hosting.spec.ts` — 7 tests that pin the contract directly: clean
  URLs, real 404 status, OG MIME, cache policy, range requests, security
  headers, path traversal.
- `deploy/Caddyfile`, `deploy/nginx.conf` — the same rules for real hosts.
- `scripts/deploy.sh` (`pnpm deploy`) — gate, publish, verify.
- `docs/SELF-HOSTING.md` — setup, cutover, rollback, and what he takes on.

## What the export actually needs (measured, not assumed)

| Requirement | Why it breaks without it |
|---|---|
| `.html` fallback | site links `/about`, export has `about.html` — every internal link 404s |
| 404 → status 404 | otherwise crawlers index a not-found page as content |
| explicit `image/png` on 7 extensionless files | `/opengraph-image`, `/projects/*/opengraph-image` → octet-stream |
| `Accept-Ranges: bytes` | the 2.6 MB case-study video cannot be seeked |
| `_next/static/*` immutable | content-hashed; anything less wastes the hash |
| HTML `must-revalidate` | otherwise a deploy never reaches a warm cache |

## Decisions

- **The reference server replaces `serve` as the test host.** The config
  already claimed "what passes here is what ships"; with `serve` that was
  true of a dev server's conveniences, not of the target. `serve` was then
  unreferenced and removed from devDependencies.
- **Caddy recommended over nginx.** Automatic certificate renewal is the
  single largest thing Vercel was doing for free, and a silently failed
  renewal takes the site down 90 days later.
- **Cloudflare Tunnel recommended for a home box.** Shao's server appears to
  be the Ryzen 9 9950X machine described in the workstation case study —
  residential, behind NAT. A tunnel avoids opening ports, works behind
  CGNAT, does not publish his home IP, and sidesteps the ISP terms that
  usually prohibit inbound hosting. Port forwarding is documented but not
  recommended.
- **CSP keeps `'unsafe-inline'` for scripts.** Next's export emits the RSC
  payload and the pre-paint theme script inline, and their contents change
  every build, so hashing would mean regenerating the header per build.
  Every *origin* is still pinned to `'self'`, which blocks the realistic
  attack. Stated as a trade in the code rather than presented as a strict
  CSP.
- **`pnpm deploy` verifies the live site and exits non-zero if wrong.**
  Publishing that cannot tell you it worked is not much better than copying
  by hand. It checks the home page, a clean URL, a case study, the 404
  status, and the OG content-type.
- **`--delete` on rsync, plus a guard against the cloud-sync duplicates.**
  `~/Documents` clones build artifacts as `name 2.ext`; publishing those
  would put stale duplicate pages on the server, so the script refuses.

## Gotchas

- **`.gitignore` had `.env*`, which swallowed `.env.deploy.example`.** Added
  a `!` exception. Verified the right way — `git check-ignore -v` exits 0
  when *any* rule matches, including a negation, so it reported "ignored"
  for a file that was not. `git add --dry-run` is the honest check. Also
  confirmed the real `.env.deploy` is still ignored.
- **Neither Caddy nor nginx is installed on this machine**, so those two
  files are the only part of this story not verified locally. The ruleset
  they implement is verified; their syntax is not. `docs/SELF-HOSTING.md`
  says so explicitly and gives `caddy validate` / `nginx -t` as the check to
  run on the server. Not hidden behind "should work".
- nginx `add_header` does not inherit into a `location` that declares its
  own, so the security headers are repeated per-location. That is nginx's
  actual rule, not redundancy — noted in the file so it does not get
  "cleaned up".

## Validate

- `pnpm validate` end to end: typecheck ✅ lint ✅ format ✅ check:photos ✅
  build ✅ check:links ✅ check:retractions ✅ test ✅ lighthouse ✅
- Playwright **180 passed, 2 skipped** (from 166) — +14 from the 7 new
  hosting tests across both projects. Every one of the other 166 now runs
  against the self-host ruleset.
- Lighthouse 13 URLs, all assertions passed. Worst performance **94**;
  accessibility 100, best-practices ≥95, SEO 100 everywhere. `/projects`
  measured 95, so **F11 is no longer at the margin** — the JetBrains Mono
  preload from the CLS work bought it back.
- CSP verified not to break hydration or the electrons instrument: the suite
  asserts zero console errors and all interactive tests pass under it.

## Not done, deliberately

DNS is untouched and production is still Vercel. The cutover needs the AWS
account that holds the hosted zone, which is not the one this machine
authenticates to, and it should happen after the server is up and verified —
the runbook sequences it that way (deploy → verify by IP → lower TTL →
switch → raise TTL), with Vercel left in place as the rollback.
