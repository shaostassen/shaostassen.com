# S14.1–S14.3 — Epic 14 tranche 1: show the work

Status: built and validated · Started: 2026-10-30 · Not yet on `main`

Requested by Shao ("the portfolio page looks kind of plain and ugly … make a
plan and start implementing"). The plan is `docs/REDESIGN.md`; this is the
first tranche. Three stories share one component (the project card), so they
were built together rather than as three half-states.

## What the diagnosis rested on

Screenshots of the built site at 1440 and 375 px. The home page was nine
identical text-only cards, a 1024 px column on a 1440 px screen, 14 px grey card
copy, 5–8 tag chips per card, and no project imagery above the fold.

One false alarm worth recording: the home page's "plates" first appeared as
empty grey boxes. That was lazy-loading in a full-page screenshot, not a bug.
Verified by scrolling first, then listing every `<img>`'s load state. The same
artifact appeared again on `/projects` and was checked the same way.

Fonts were reviewed and deliberately not changed. See REDESIGN.md.

## Decisions

- **Covers are real or absent.** FaultLab's only canvas is 88 px tall and nearly
  empty, so it gets a readout tile ("95.9M fault pairs") rather than a weak
  screenshot. Huey has no cover for a different reason: the only image is in the
  team's repo, and using it is Shao's call. Both show as readout tiles.
- **Bits → Messages cover is level 04**, not level 01. Level 01 is prose; level
  04 draws the waveform with the receiver's sample points walking across it
  beside the real +3.90% / −4.64% budget.
- **Demostack's cover is a 420 px cut enlarged 2×.** The source frame is a small
  UI in a lot of dark space. Slightly soft; noted rather than hidden.
- **Lead trio is Fast Robots, Electrons, Blaze and Heat.** A real hardware
  photo, a live instrument, a running simulation. A content call, so it is one
  typed file and Shao's to change.
- **Metric once per card.** Also keeps the existing `getByText("~21× on 32
  cores")` test valid without editing it.

## A defect the gates caught, and one they did not

1. A first version wrapped each card in an `<article>` inside the link. The
   `landing card links to the case study` test failed: the link had **no
   accessible name**. A link's name is computed from its content, and a
   sectioning element inside it is skipped. The page looked and read normally.
   Axe did not flag it. Fixed (a `div`), and `every project link … has an
   accessible name` now pins it on both pages. Confirmed to fail against the
   defective build before the fix, so it is a real guard.
2. With the name restored, the link's name began with the cover's alt text and
   then repeated the project's title and description. Covers inside cards are
   now `alt=""`.
