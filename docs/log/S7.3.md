# S7.3 — Share-correctness: per-page metadata, full-site budgets, real 404

Status: doing · Started: 2026-07-31

Origin: not from the PLAN backlog. Shao asked for a codebase review on
2026-07-31; these were the top three findings and he picked them as one
scope. Built on `feat/site-review` at his request — a deliberate deviation
from the direct-to-main rule in `git-workflow`, for this story only.

## The story

Three defects that share a theme: the site is correct when *you* look at
it, and wrong when *someone else* encounters it — via a shared link, a
crawler, or a URL that no longer exists.

**1. Every sub-page shares as the homepage.** Only `<title>` and
`<meta name="description">` were per-route. `og:*` and `twitter:*` came
from the root layout on every page, so `/projects/parallel-spgemm`
advertised:

```
og:title       Shao Stassen
og:description Engineer working across embedded systems, robotics…
og:url         https://shaostassen.com     ← the homepage, not the page
twitter:title  Shao Stassen
```

The per-project OG *image* was correct (file convention, S7.2); the title,
description and URL beside it were not. Paste a case study into LinkedIn
or an application and it renders a generic card pointing at `/`. Scrapers
that treat `og:url` as canonical drop the case study's own identity.
No `<link rel="canonical">` existed anywhere on the site.

This half-misses S7.2's own acceptance criterion (PLAN §11): "per-page
`<title>`/meta/OG/Twitter cards".

**2. Lighthouse gated one URL.** `lighthouserc.json` collected
`http://localhost/` only. `/about` (priority portrait), `/projects`, and
every case study with a plate gallery were never measured — while
`/colophon` told visitors "Lighthouse, asserted on every build — not a
one-off screenshot". True of the home page; not of the site. "Instrument,
don't guess" is PLAN principle #4, so the claim and the config have to
agree.

**3. The 404 was stock Next.js.** The one page nobody designed, and the
one a stale shared link lands on.

## Approaches considered

**Metadata (finding 1)**

- *(a) Hand-write `openGraph`/`twitter`/`alternates` per page.* Explicit,
  but seven copies of the same shape — it drifts the first time a page is
  added, which is exactly how the bug arose.
- *(b) A `pageMetadata()` builder in `src/lib/metadata.ts`.* One function
  takes `{ title, description, path, type }` and returns the whole
  `Metadata` object. Pages declare facts, not plumbing. **Chosen.** It
  also makes the invariant testable in one place: any route whose metadata
  goes through it cannot ship a wrong `og:url`.
- *(c) Push it into the root layout.* Impossible — under `output: export`
  the layout has no route knowledge.

The decisive detail is that Next merges metadata across segments
**shallowly**: a child's `openGraph` object replaces the parent's whole
object rather than merging field-by-field. So the builder must re-emit
`siteName` and `twitter.card` itself, or setting a page title would
silently drop `og:site_name` and `twitter:card` from every sub-page —
turning one bug into two. File-convention OG images are the exception and
still merge in per-segment.

**Budgets (finding 2)**

- *(a) Drop `url` and let LHCI auto-discover every HTML file in `out/`.*
  Zero-maintenance, but it would also audit `404.html` and the
  `styleguide` stub — pages with no meta description, which fail SEO = 100
  for a reason that is not a defect.
- *(b) Enumerate the real routes.* **Chosen.** Six URLs: the four content
  pages, plus one case study and the colophon. Explicit about what is
  promised, and a new route joining the list is a deliberate act.

**404 (finding 3)** — `app/not-found.tsx` as a server component reusing
`Section`/`Container`/`Annotation`, no new primitives. The instrument
framing gives the page an honest reading: a 404 is a measurement that came
back empty.

## Risks

- **Shallow merge** (above) — mitigated by asserting `og:site_name` and
  `twitter:card` on a sub-page, not just the landing page.
- **File-convention OG images could be overridden** by declaring an
  `openGraph` object. The builder never sets `images`, and the existing
  per-project image test pins it.
- **New routes may fail the ≥ 90 performance floor** once they are actually
  measured. That is the point of the change. If one fails it gets fixed or
  logged explicitly — the floor is not moving again.
- `not-found.tsx` changes the copy the existing 404 tests match on
  (`/definitely-not-a-page` in smoke + a11y).

## Decisions

- **`pageMetadata()` in `src/lib/metadata.ts`** is the only place any route
  builds title / description / canonical / OG / Twitter. Pages pass facts
  (`title`, `description`, `path`), not tag shapes.
- **Canonical is deliberately absent from the root layout.** If it were set
  there, a page that forgot to call the builder would silently inherit
  `canonical: "/"` — a wrong canonical is worse than none, because it tells
  crawlers to attribute the page to the homepage. Missing is a visible
  omission; wrong is an invisible one.
- **`og:type: article` for case studies**, `website` everywhere else.
- **The 404 claims no canonical and sets `robots: { index: false }`.**
- **Lighthouse audits 7 explicit URLs**, not auto-discovery: auto-discovery
  would also grade `404.html` and the `styleguide` stub, which have no meta
  description and would fail SEO = 100 for a non-defect. One case study
  (`fast-robots`) represents the template — it is the heaviest, carrying a
  three-plate gallery.
- **Colophon now quotes the worst route, not the best** — `94+` rather than
  a single page's score, with the method stated in the caption.
- **404 focus rings match the site's existing inline-link pattern** (browser
  default) rather than the nav's explicit 2px accent ring. Making the 404
  the one page that differs would be worse than the inconsistency; logged
  as F10 to fix everywhere at once.

## Gotchas

- **Next merges metadata across segments shallowly, and it cost an OG
  image.** Declaring `openGraph` on a page replaces the parent's object
  outright. Two consequences, both silent:
  1. `og:site_name` and `twitter:card` vanish from that page unless the
     builder re-emits them.
  2. A file-convention `opengraph-image` inherited from an **ancestor**
     segment is dropped. One from the **same** segment still merges — which
     is why case studies kept their per-project image while `/about`,
     `/contact`, `/projects`, `/coursework` and `/colophon` silently lost
     theirs.

  Caught by diffing a stashed baseline build against the new one rather
  than by reasoning — worth the 40 seconds. Fix: `OG_IMAGE` in
  `src/lib/site.ts` is the single source for the site-wide image;
  `opengraph-image.tsx` reads its `size`/`alt` from it, `pageMetadata()`
  attaches it, and `hasOwnOgImage: true` opts the case studies out. Pinned
  by an assertion on every route in `seo.spec.ts`.
- **Hand-stating the image URL loses Next's content hash**
  (`/opengraph-image?72b8b832…`), which is what busts social platforms'
  preview caches. Replaced with an explicit `?v=1` to be bumped by hand
  when the OG image design changes. Documented at the constant.
- **LHCI `staticDistDir` wants file paths.** `http://localhost/about`
  does not resolve against the exported tree; `about.html` does. Nested
  routes likewise: `projects/fast-robots.html`.
- `metadata` exports **do** work in `not-found.tsx` (title + robots landed
  in `out/404.html`), which is not obvious from the docs.

## Evaluate

- 404 checked at 375 / 768 / 1440 in both themes: no horizontal overflow at
  any size, the link row wraps to two lines at 375, and the heading breaks
  cleanly.
- Keyboard pass on the 404: skip link first, then nav, then the four
  recovery links, then the footer. Every stop has a visible ring (see F10
  on ring consistency).
- Design system: no new components, no new tokens, no new colors. `Section`
  / `Container` / `Annotation` / `GridBackdrop` reused as-is.
- Copy read against `content-voice`: "Nothing at this address" — plain,
  no cleverness, no apology. Microcopy is lowercase mono like the hero's
  link row.
- Acceptance: this story has no PLAN §11 entry (it is review-derived), so
  the bar was the three findings. All three are closed, and the S7.2
  criterion they undercut — "per-page `<title>`/meta/OG/Twitter cards" —
  now actually holds, asserted per route.
