# S3.10 — bits-to-messages: the WebSocket bridge

Status: done · Started: 2026-08-21 · Shipped: 2026-08-21

Follow-on to S3.9, requested directly by Shao ("Finish the websocket bridge").
The Smith & Nephew carve-out still stood; S4.2 was not touched.

## What it is

The half of the project's thesis that everything else could only assert. The
browser instrument and the server share an engine and were *trusted* to agree;
the bridge wires them together, so the LIVE panel draws its trace from bytes
that actually crossed a `/dev/ttys*`.

`/projects/bits-to-messages/lab` holds **96/100/100/100** at 22 kB.

## Proven end to end, not asserted

Driven by hand against a running server before shipping. Both directions, plus a
third-party observer:

| Step | Result |
|---|---|
| external python process writes `READ:TEMP?\r\n` into `/dev/ttys000` | browser logs `rx 52 45 41 44 3A 54 45 4D 50 3F 0D 0A`, 12 bytes |
| instrument replies | browser logs `tx` with the echo and `23.19` |
| type `*IDN?` in the browser, press send | a separate process reading the device node receives `*IDN?\r\nBITS-TO-MESSAGES,VIRT-UART,0,0.1.0\r\n> ` |
| set "receiver 12% off rate" in the browser | that same external process receives `Z\x99\x84\x9e…` instead — real bytes, mis-sampled by the core model |

The last row is the one worth keeping: the browser damaged a real link, the
corruption was computed by the same engine that draws the simulated levels, and
a program that knows nothing about any of this observed the damage.

## Decisions

- **Hand-rolled RFC 6455, no `ws` dependency.** Not purity for its own sake:
  this is a project about what a byte stream is not, and WebSocket framing is
  that exact problem solved a third way. Level 08 delimits with a reserved byte
  and pays one byte per 254; Modbus in level 11 delimits with silence and pays
  nothing but must watch the clock; WebSocket puts a length in front. Same
  problem, three answers — worth 200 lines. The handshake is checked against the
  example in RFC 6455 §1.3 rather than against itself.

- **It never connects on its own, and that is a site constraint as much as a
  UX one.** This host is static, so there is no bridge to reach from the
  published page; an auto-connecting panel would only ever log a failed
  connection, and the gate forbids console errors. Explicit click, and the idle
  state explains the architecture instead of looking broken. Pinned by a test
  that asserts no WebSocket is opened and no console error is logged.

- **LIVE is a mode, not a twelfth rung.** The ladder closed at eleven in S3.9
  and stays closed; the panel is set apart in the nav and the closing note still
  reads "All 11 rungs are drawn". Pinned by a test.

## Two defects found by building it

- **Node counts an upgraded socket as a live connection for ever.** The client
  destroying its end does not decrement it, and `closeAllConnections()` does not
  reach it — an upgraded socket is no longer the HTTP machinery's business. Only
  a server-side `destroy()` frees it, and until one happens `server.close()`
  never calls back. Every bridge test hung in teardown (71 s of timeouts) until
  the sockets were tracked and torn down explicitly. Isolated against a bare
  `http.Server` to confirm it was Node's behaviour and not mine, then pinned by
  a test asserting `close()` returns in under a second.

- **A `<button>` inside a `<label>` takes the label's text as its accessible
  name.** Both LIVE buttons sat in a field whose label was a non-breaking space,
  so a screen reader announced them as blank and Playwright could not find
  "connect" by role at all. Caught by the site suite rather than by a type or a
  review — the argument for testing by role instead of by selector.
