# S13.1 — Hardware inventory tool

Status: done · Started: 2026-10-23 · Shipped: 2026-10-23

Requested directly by Shao: an internal dashboard for tracking his personal
hardware inventory (dev boards, test equipment, parts — low volume, edited by
hand), reachable from shaostassen.com. New epic (E13, internal tools) — this
is not a case study and carries no portfolio content.

## Approaches considered

1. **New standalone app/subdomain**, own backend + database — rejected by
   Shao; he wants it inside this repo, edited as a file, not a separate
   service to run and maintain.
2. **Plain data file + client-side password gate, committed as-is** — the
   simplest fit for "no database, no server" (PLAN §3/CLAUDE.md), but this
   repo is public (`shaostassen/shaostassen.com`), so a committed item list
   would be readable in GitHub regardless of any gate on the live page.
   Rejected by Shao once that was surfaced — he wants real privacy, not just
   obscurity.
3. **Chosen: build-time AES-256-GCM encryption, decrypted client-side.** The
   item list never touches git (Vercel env var `HARDWARE_DATA_JSON`, synced
   from a gitignored local file); `src/content/data/hardware.ts` encrypts it
   at build time with a key derived from `HARDWARE_PASSWORD` (PBKDF2-SHA256,
   250k iterations); the page ships only ciphertext + salt + iv.
   `src/lib/hardware-crypto.ts` re-derives the same key client-side via
   WebCrypto and decrypts on a correct password. No server-side auth exists
   or is possible under `output: 'export'` — this is the actual protection
   layer, not the password prompt UI by itself.

## What shipped

- `/tools/hardware` — new route, `robots: noindex`, added to
  `unlistedRoutes` in `src/lib/routes.ts` (excluded from sitemap, nav, and
  the `siteRoutes()`-driven a11y/SEO/Lighthouse sweeps; checked by hand
  instead).
- `hardwareItemSchema` (src/content/schema.ts): name required, everything
  else (category/location/status/notes/quantity) optional free text — no
  enum friction for a list he wants to edit quickly.
- `hardware-inventory.example.json` (committed template) /
  `hardware-inventory.local.json` (gitignored, real data) — he edits the
  local file directly; `pnpm hardware:sync` validates it and pushes it to
  Vercel's `HARDWARE_DATA_JSON` for production + preview. `HARDWARE_PASSWORD`
  is set once, directly, via `vercel env add` — never generated or seen by
  Claude, never in a file.
- No new deps: Node's `crypto` (build) and the browser's `crypto.subtle`
  (client) only, same no-new-deps bar as S8.1.

## Known limits (stated on purpose, not a gap to close later)

- Decrypted items are cached in `sessionStorage` after unlock, for
  convenience across a refresh in the same tab — cleared when the tab/
  browser session ends.
- A brute-force attempt against the ciphertext is the real threat model now
  (not "can someone find the URL") — pick a real passphrase, not a short PIN.
